1 · What this platform does

Broadband ISPs face attacks where intruders take over FTTH ONT/router accounts and change customer credentials, cutting service. Recovering customers one by one is slow and costly. This platform detects those attacks from authentication logs, correlates them geographically across all 18 Laos provinces (GeoAI), raises prioritized hotspot alerts, and performs batch recovery via the ACS — approved by an operator with one click, automatically by the AI, or by a field edge sensor (Raspberry Pi). Attacks are also streamed to a global GeoIP attack map that plots each source's real-world origin as it strikes the Laos network.

3 · Process flow — attack, detection, recovery

Attackerorigin province · credential stuffing
→
Failed logins on ONTs+ credential change when the attacker gets in → service down
→
AI detection≥ 5 fails / 60 s → suspicious · cred_change → compromised
→
GeoAI zone scoringrisk 0–1 per province · ≥ 3 affected ONTs → hotspot alert (low→critical)
→
Batch recovery (ACS)operator click · AI auto-approve · or edge sensor
→
Reportlive event feed · attack history · analytics (24 h / 30 d / 12 m)

During an attack the map draws the origin → target path as an animated tracer line, colors affected ONTs orange/red, and grows the target zone's risk ring. Attacker source IPs are ranked over a 5-minute window. Every alert carries a recommended action; recovery resets all affected ONTs in the zone and restores service in one step.

A separate view of the same attacks, answering "where in the world is this coming from". Every ONT takeover on the dashboard is shipped to the map at attackmap.laopadit.com, which draws an animated arc from the attacker's real country to Laos, with a live event table (IP · country flag · service) and per-country / per-IP counters. It is the actual open-source geoip-attack-map project fed by real Logstash, deployed as a three-container Docker stack (./deploy_attackmap.sh).

It is real Elasticsearch + Kibana, fed by the same Logstash pipeline; dashboards are provisioned by setup_kibana.py (data view + saved objects via the Kibana API).

7 · API reference

EndpointPurpose
POST /api/login{"user","pass"} → session token; all other endpoints require it as the X-Auth header
GET /api/stateFull live state: ONTs, zones + risk, alerts, events, active attack path, attacker IPs, KPIs
GET /api/stats?range=day|month|yearAttack history bucketed for the analytics charts, with per-zone and per-origin breakdowns
POST /api/logReal-case ingestion: auth events from OLT/ACS/RADIUS collectors (single event or array)
POST /api/recover/<zone>?by=<label>Batch-reset every affected ONT in a zone; label shows in the feed
POST /api/auto{"enabled":bool} — AI auto-approved recovery on/off
POST /api/attackDemo: launch a cross-province attack (simulation mode only)
